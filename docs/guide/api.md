# API

`use gideon` gives every public entity of the library: the kinds, `GIDEON_NAN`, the rows and every operator. The
modules behind it can be used one by one; all but `gideon_kind_parameters` and `gideon` are generated by
`scripts/gen_gideon.py`.

| Module | Public entities | Count |
|---|---|---|
| `gideon` | everything below, and `I4P`, `I8P`, `R4P`, `R8P` from PENF | — |
| `gideon_kind_parameters` | `R_P`, `GIDEON_NAN` | 2 |
| `gideon_tables` | the rows, `FD_*`, `FV_*` (and `R_P`: the module's default accessibility is public) | 134 |
| `gideon_fd_centred` | `gideon_fd_face_c<p>`, `gideon_fd_dN_c<p>`, `gideon_fd_face_dN_c<p>` | 48 |
| `gideon_fd_upwind` | `gideon_fd_face_{ur,ul}<p>` (one-sided), `gideon_fd_face_{bl,br}<p>` (upwind-biased) | 26 |
| `gideon_fv_centred` | `gideon_fv_face_c<p>`, `gideon_fv_face_dN_c<p>`, `gideon_fv_dN_c<p>` | 48 |
| `gideon_fv_upwind` | `gideon_fv_face_{ur,ul}<p>`, `gideon_fv_face_dN_{ur,ul}<p>`, `gideon_fv_dN_{ur,ul}<p>` | 156 |
| `gideon_deconvolution` | `gideon_fv_point_c<p>`, `gideon_fd_average_c<p>` | 10 |
| `gideon_dispatch` | the run-time order dispatchers of the 1-D kernels | 54 |
| `gideon_operators_3d` | `gideon_{fd,fv}_{gradient,divergence,curl,laplacian}_c<p>` and their 8 dispatchers | 48 |

Every procedure is a `pure subroutine` with `!$acc routine seq` and `!$omp declare target`: callable from host code,
from an OpenACC compute region and from an OpenMP target region alike.

## Kinds

| Entity | Module | Meaning |
|---|---|---|
| `R_P` | `gideon_kind_parameters` (PENF's) | the real kind of every operator: R8P by default, R4P with `-D_R_P_IS_R4P`, R16P with `-DPENF_R16P -D_R_P_IS_R16P` (host only), one per build ([Precision](/guide/precision)) |
| `GIDEON_NAN` | `gideon_kind_parameters` | `real(R_P), parameter`: a quiet NaN of `R_P` (`0x7FC00000`, `0x7FF8000000000000`, `0x7FFF8000…0`), the result of a dispatcher called with an order that has no kernel |
| `I4P`, `I8P`, `R4P`, `R8P` | `gideon` (PENF's) | integer and real kinds of 32 and 64 bits; the `order` argument of the dispatchers is `integer(I4P)` |

R16P is not re-exported by `gideon`: a client of the R16P build takes `R_P`, or uses PENF's `R16P` directly.

## 1-D kernels

```fortran
pure subroutine gideon_<data>_<op>_<bias><order>(q, [ds,] r)
real(R_P), intent(in)  :: q(LO:HI) ! the window by offset, explicit shape (Conventions)
real(R_P), intent(in)  :: ds       ! the grid step: derivatives only (dN, face_dN)
real(R_P), intent(out) :: r        ! the result: f (face value), d (derivative), v (point value, average)
```

288 kernels; the name, the window and the order of each are in the table of [Operators](/guide/operators#every-kernel).
The result is a derivative divided by `ds**N` inside the kernel (`/ds/ds` for `fd`, `/(ds*ds)` for `fv`), so `ds = 1`
gives the undivided difference.

```fortran
use gideon
real(R_P) :: u(-2:102), du, uf
integer   :: i
call gideon_fd_d1_c6(u(i-3:i+3), 0.01_R_P, du) ! sixth-order first derivative at node i, point values
call gideon_fv_face_ul5(u(i-4:i), uf)          ! fifth-order value at the face i+1/2 from the five cells on its left
call gideon_fd_face_d1_c4(u(i-1:i+2), 0.01_R_P, du) ! fourth-order first derivative at the face i+1/2, point values
call gideon_fd_face_bl5(u(i-2:i+2), uf)        ! fifth-order upwind-biased value at the face i+1/2, point values
```

## Run-time order dispatchers

```fortran
pure subroutine gideon_<data>_<op>_<bias>(order, q, [ds,] r)
integer(I4P), intent(in)  :: order                  ! the order of accuracy
real(R_P),    intent(in)  :: q(lo(order):hi(order)) ! the window of that order
real(R_P),    intent(in)  :: ds                     ! derivatives only
real(R_P),    intent(out) :: r                      ! GIDEON_NAN if no kernel has that order
```

## 3-D operators

```fortran
pure subroutine gideon_<data>_gradient_c<p>(qx, qy, qz, dxyz, g)                         ! g(3)
pure subroutine gideon_<data>_divergence_c<p>(vx_x, vy_y, vz_z, dxyz, div)               ! div
pure subroutine gideon_<data>_curl_c<p>(vy_x, vz_x, vx_y, vz_y, vx_z, vy_z, dxyz, c)     ! c(3)
pure subroutine gideon_<data>_laplacian_c<p>(qx, qy, qz, dxyz, lap)                      ! lap
real(R_P), intent(in) :: qx(-S:S), ..., dxyz(3)   ! S = p/2; one contiguous stencil per axis through point 0
```

`<data>` is `fd` (point values) or `fv` (cell averages), `<p>` 2, 4, 6, 8 or 10. A stencil is named by the component
and the axis it runs along: `qx` the scalar along x, `vy_x` the y component along x. The gradient and the divergence
call the d1 kernel of the order along each axis, the Laplacian the d2 kernel, the curl the d1 kernel on the six
off-axis stencils, summed in x, y, z order (ADAM's, so the values are ADAM's bitwise). The dispatchers
`gideon_<data>_<op>_c(order, ...)` take the same stencils with bounds `-(order/2):order/2` and return `GIDEON_NAN` in
every component for an order without a kernel.

## Rows

`gideon_tables` holds one named constant per row, an exact rational folded by the compiler (`p._R_P/q._R_P`). A
centred row is half the stencil in pair form: index `m` multiplies the pair of offsets `m` and `-m` (node or cell; index
0 the centre) or `m` and `1-m` (face). An upwind row holds the right-side stencil, cells (or points) `1..S`, the face
nearest first; the left-side kernels and the cell derivatives read the same rows. A biased row (`FD_BFACE_S<k>`) holds
the right-biased stencil by offset, `1-k..k+1`; the left-biased kernel reads it mirrored. Every row, with the kernels
